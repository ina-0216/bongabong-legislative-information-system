CHAPTER IIITECHNICAL BACKGROUNDThis chapter contains the technicality of the project. How the present system will work, details of technology to be used in creating, deploying and how will the project work.Technicality of the StudyThe legislative process of the Sangguniang Bayan (SB) of Bongabong, Oriental Mindoro is carried out almost entirely through manual, paper-based procedures. The SB is composed of the Vice Mayor as the presiding officer, eight (8) regularly elected councilors, and several ex-officio members. All ordinance-related activities are handled by the Sangguniang Bayan Secretaries and staff. The process begins when a councilor prepares a draft ordinance, which must contain mandatory fields such as an Ordinance Number, Title, Proponent, Explanatory Note, Enacting Clause, Provisions, Penalty Clause, and Effectivity Date — all filled out by hand. Supporting documents such as national laws, budget plans, and technical reports are also compiled manually alongside the draft.Once the draft is ready, it is formally introduced during a session in what is called the First Reading, where only the title and number are read aloud and no debate takes place. The Vice Mayor then assigns it to the appropriate committee. If it covers multiple areas, it is referred to more than one committee for Joint Committee Hearings. The committee then holds Public Consultations to gather feedback, either through face-to-face meetings or via Zoom or Google Meet. Residents are notified by a liaison officer through physical letters, and those who wish to respond must also send their feedback in writing. All feedback is manually tallied and compiled into a Committee Report, where the majority opinion — based on a 50% + 1 or two-thirds rule — determines the recommendation.If the Committee Report is favorable, the ordinance moves to the Second Reading, where council members debate and propose amendments using circulated physical documents. Once agreed upon, it proceeds to the Third Reading for the final vote, which is done verbally or by raising of hands and recorded manually by the SB Secretary. After approval, the ordinance is forwarded to the Municipal Mayor for signature, then transmitted to the Sangguniang Panlalawigan of Oriental Mindoro for a final legal review. Once cleared, it is published through bulletin boards, Facebook, and the liaison officer. The physical copies are stored in the SB office; however, there is no digital archive, making retrieval slow and difficult as old records are disorganized and fragile.Details of Technology to be Used in the StudyIn this proposed study, back-end technologies and databases will be utilized to process secure data and synchronize updates. The developers will build a custom back-end using Node.js and Express.js to process secure API requests and manage server logic. For the database, MongoDB, a highly flexible NoSQL database, will be utilized to store the ordinance details and tally the live votes from the citizens. JSON Web Tokens (JWT) will handle secure user authentication to ensure admins have the right editing access. To handle the heavy PDF files of the signed laws, the system will integrate a specialized cloud storage solution like Cloudinary or AWS S3 so the public can view them without degrading server performance.On the front-end, technologies will be used to create the UI (user interface) and UX (enhance the user experience) for the digital dashboard and consultation portal. The developers will use HTML (Hypertext Markup Language) to build the main structure of the pages. Instead of relying heavily on large frameworks, Vanilla CSS (Cascading Style Sheets) will be used to design custom status badges and color-coded voting bars. JavaScript will be used to process local interactions on the screen.The framework and libraries will help save development time, enhance code quality, and facilitate feature building. To make the website fast and responsive, the developers will use React.js along with Vite. This allows the dashboards to update instantly without having to reload the whole browser. The system will also integrate React-pdf so users can read the official PDF documents directly on the website. Recharts or Chart.js will be used to turn the voting numbers into easy-to-read pie charts for the Committee Reports.The web application will be developed using Visual Studio Code to facilitate writing and editing the source code. Google Chrome and Microsoft Edge will be used to test, inspect, and fix bugs in a real-world browser environment. Finally, to deploy the project and make it accessible on the internet 24/7, platforms like Vercel (for the front-end) and Render (for the Node.js back-end) will be utilized as the web servers.The minimum technology requirements for implementing the web application for the Administrative Dashboard include a desktop PC or laptop with at least an Intel Core i3 or equivalent processor, a minimum of 4 GB of RAM to handle the data smoothly, and Windows 10/11 or macOS. For regular citizens, any standard computer or modern smartphone with an updated web browser is enough to visit the consultation portal. A stable internet connection is absolutely mandatory for both the admins and the public since the voting and document viewing happen in real time over the cloud.
